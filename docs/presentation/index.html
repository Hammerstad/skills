How I work with AI agents and skills

Eirik Mildestveit Hammerstad

First in a series on how we use AI. This one is inspiration: how I build software with AI agents today. Plan: who builds software, how one piece of work moves through a team, then the same work done with skills.

Writes the code

Keeps it safe

Ops / DevOps

Ships it, keeps it running

A typical team. Product decides what and when, UX how it feels. The architect shapes the system, the tech lead guides the team's choices. Developers build, QA and security check, ops ships and runs it. Each role has its own responsibility and its own checklist, written down or in their head.

How an issue usually flows

One piece of work, issue 42. Click to move it. The idea comes from a user or the PM, sometimes UX. Refined by PM, UX and tech lead. A developer builds it, another developer and QA review it. Then merge and release. Every arrow is a handoff between people, and work waits at each handoff.

skills/grill-me/SKILL.md

---
name: grill-me
description: Interview the user about a plan
  or design until every decision has been made.
---

## The method

Interview me about every part of this plan until
we share the same understanding of it.
For each question, give your recommended answer.

Ask the questions one at a time, and wait for my
answer before asking the next one.
A skill is a recipe for one step of the work, written in plain text. Agent Skills is an open standard. The same folder works in Claude, Copilot, Cursor, Codex, and in Databricks and Snowflake. The agent only sees the name and description until a task matches. Then it reads the rest and follows it. Click: grill-me, the actual file behind the session I used to plan this talk. No code. Anyone who can write a checklist can write a skill.

Nineteen skills. Helpers first: setup-repo prepares a repo, labels hold the state of each issue so any agent can pick up where another stopped. The rest are grouped by phase. Decide is where most of my time goes. Capture turns a decided plan into issues. Build, review and ship are mostly done by agents. Two skills run a phase over the whole backlog: grill-issues for decisions, work-loop for build to ship. Several are borrowed from Matt Pocock's skills and adapted.

The same work, with skills

The same piece of work. It starts with me and an idea, and a grill session: grill-me, plan-epic for big work, or diagnose for a bug. I make the decisions. to-issues splits the result into small issues. create-issue and triage are used sometimes, not always. From build to merge, work-loop runs on its own. Each skill is tagged with the role it stands in for. The reviewer is a separate agent that has not seen the code being written.

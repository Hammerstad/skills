First in a series on how we use AI. This one is inspiration: how I build software with AI agents today. Plan: how a team builds software, how one piece of work moves through it, then the same flow with skills.

A typical team. Product decides what and why, UX how it feels, tech lead how it fits. Developers build, QA and security check, infrastructure and ops run it. Each role has its own responsibility and its own checklist, written down or in their head.

How an issue usually flows

One piece of work, issue 42. Click to move it. Idea from a user or the PM. Lands in the backlog. Refined by PM, UX and tech lead. A developer builds it, someone else reviews, QA and security check. Then merge and release. Every arrow is a handoff between people, and work waits at each handoff.

What is a skill?

grill-me

When: I have a plan and want it questioned

  1. Ask one question at a time
  2. Give your recommended answer
  3. Look in the code instead of asking, when you can
  4. Stop when every decision is made

  or design until every decision has been made.

## The method

Interview me about every part of this plan until
we share the same understanding of it.
For each question, give your recommended answer.

Ask the questions one at a time, and wait for my
answer before asking the next one. If a question
can be answered by exploring the codebase, explore
the codebase instead of asking me.

A Markdown file. The agent loads it when the task matches.

A skill is a recipe for one step of the work, written in plain text. The agent sees the name and description. When my request matches, it loads the rest and follows it. This is the actual file behind the session I used to plan this talk. No code. Anyone who can write a checklist can write a skill.

Nineteen skills, grouped by the same phases as the flow. Capture gets ideas onto the board. Decide is where most of my time goes. Build, review and ship are mostly done by agents. work-loop chains build, review and ship and runs on its own. Helpers: GitHub labels hold the state of each issue, so any agent can pick up where another stopped. Several are borrowed from Matt Pocock's skills and adapted.

The same flow, with skills

Same board, same issue. Each person is replaced by a skill, tagged with the role it stands in for. I am involved at two points: the idea, and the decisions in the grill session. From build to merge, work-loop runs on its own. The reviewer is a separate agent that has not seen the code being written.
